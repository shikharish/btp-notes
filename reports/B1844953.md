# Lodash `keyBy`: expected behavior

**The reported output reproduces in Lodash 4.17.15, but it follows the documented contract.** `keyBy` transforms keys, not values. The returned functions become property keys; both stringify to identical source text. Consequently the second input, `'bar'`, overwrites `'foo'` at that key. The functions are distinct closures, but ordinary object keys do not preserve function identity.

The requested `{foo: function, bar: function}` would require value mapping. The historical documentation does not promise that behavior for `keyBy`; no incorrect documentation promise was found.

## Experiment notes and challenges

The explanation under test is that the iteratee transforms keys rather than values, predicting the reported collision. The retained harness exercises identity/string keys, distinct source strings, and explicit coercion. The saved log contains one run of each implementation; the review rerun agrees. This synchronous call requires no timing explanation. The earlier claim that the hypothesis was recorded before acquisition/execution is unsupported by the retained artifacts.

| Control | Prediction / observed result |
|---|---|
| Exact reported call | Predicted function-source key and `'bar'`; reproduced in all three implementations. |
| Callback instrumentation | Observed calls `['foo']`, then `['bar']`, each with exactly one argument. Returned functions are unequal identities but equal source strings. Manually calling them on `{foo:10, bar:20}` returns 10 and 20, confirming intact closures. |
| Identity iteratee | `{foo:'foo', bar:'bar'}`: keys change as requested; values remain inputs. |
| Constant `'same'` key | `{same:'bar'}`; reversing inputs gives `{same:'foo'}`. Collision is not function-specific. |
| Original same-source functions with reversed input | Final function-source property contains `'foo'`, confirming last-input selection. |
| Two functions with different source text | Two distinct properties, with original string values. Function return type alone does not cause loss. |
| Functions with custom `Symbol.toPrimitive` returning the input key | `{foo:'foo', bar:'bar'}` and logged coercion hints; still no function values. |
| Plain JavaScript assignments using the two returned functions as keys | Same single property and `'bar'`. This is a language-only control, not the reproduction pipeline. |

An additional API contrast also passed: `mapValues(keyBy(['foo','bar']), key => function() { return this[key]; })` yields `foo` and `bar` function-valued properties, whose calls return 10 and 20. This is not claimed as a reproduction or a patch. Its separate contract is documented under `_.mapValues` at `repo/doc/README.md:7867–7873`, and implemented by `mapValues` at `repo/lodash.js:13396–13404` (iteratee result is assigned as the **value**).
