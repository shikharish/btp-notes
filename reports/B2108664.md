# B2108664 — confirmed defect, narrowed title

**VERIFIED_END_TO_END** for the reported body. Unmodified Moment 2.18.1 public `moment(string).format()` returns `2017-01-02T01:00:00-05:00` for `Mon, 02 Jan 2017 06:00:00 -0800`, instead of `09:00:00-05:00`. Native Date wrapped in Moment returns the latter. Title's +0000 case is correct, not defective under these conditions. See CONTRACT.md for historical API adjudication.

2. **OBSERVED** `" -0800"` length 6 reaches the switch in `configFromRFC2822` at `repo/moment.js:2127-2141`; no case 6 exists. **STATIC/OBSERVED** default `repo/moment.js:2140-2141` sets GMT +0000. This is the earliest responsible divergence, also present in original `configFromRFC2822` at `repo/src/lib/create/from-string.js:140-154`.
3. **OBSERVED** `configFromRFC2822` replaces match and reconstructs input at `repo/moment.js:2143-2148`; `_i` becomes `Mon, 02 Jan 2017 06:00:00 +0000`. The anonymous `Z`/`ZZ` parse callback at `repo/moment.js:2756-2759` sets `_useUTC=true`, `_tzm=0` using `offsetFromString` (`repo/moment.js:2768-2782`).
4. **OBSERVED** `configFromArray` at `repo/moment.js:2265-2269` constructs 06:00Z and subtracts zero minutes; trace shows before/after unchanged. Correct -0800 should subtract -480 minutes to produce 14:00Z.
5. **OBSERVED** public `format` at `repo/moment.js:3301-3307` displays the wrong instant as 01:00-05:00. Direct epoch assertions (`experiments/pipeline.js:15-17`) demonstrate the defect precedes display. No assumed causal link required for the exercised path.
