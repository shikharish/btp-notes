# Bug found: Webpack corrupts Lodash's imported shorthand properties

The reported build error reproduces with **lodash-es 4.11.1 and Webpack 2.1.0-beta.5**. Webpack turns a valid shorthand property such as `{chunk}` into `{__WEBPACK_IMPORTED_MODULE_0__chunk__["a"]}`—a member-access expression without a property key. UglifyJS reports the resulting invalid JavaScript, mapping its location back to `array.default.js:67,0`.

This is a demonstrated **Webpack import-rewriting bug**, not a demonstrated Lodash implementation bug. Even without UglifyJS, the emitted bundle is syntactically invalid. The finding is scoped to the tested versions and minimal no-loader configuration; the reporter's exact installation is unavailable.

**Observed dynamic values:** the delegating runtime wrapper `experiments/trace.js` records the actual template invocation as `name="chunk"`, `id="default"`, `range=[2330,2335]`, original location line 67 columns 2–7, imported variable `__WEBPACK_IMPORTED_MODULE_0__chunk__`, and used export `"a"` (`evidence/trace-min-build.log`). Acorn identifies that exact range as a shorthand property's key/value (`evidence/validation.log`).

**Generated output, not upstream source:** `evidence/bundles/plain.js:23863–23864` contains:

```js
/* harmony default export */ exports["a"] = {
  /* harmony import */__WEBPACK_IMPORTED_MODULE_0__chunk__["a"], /* ... */
```

Node rejects the `[` at line 23864. Acorn also rejects this bundle in **ES2015** mode while accepting original `array.default.js`; this is not merely a valid ES2015 construct unsupported by an old ES5 minifier. The executed Uglify parser's `object_` routine expects `:` after the generated identifier (`env/build/node_modules/uglify-js/lib/parse.js:1249–1280`); `expect_token` formats the reported exception at `:713–720`.

The root-import graph includes category modules despite only `camelCase` being requested: the original build lists 573 modules, versus 21 for the direct-import control. The claim here is malformed rewriting, not that retaining these dependencies is itself a tree-shaking defect.

## Conclusion and boundaries

**Bug found; reproduced=true for the named lower-bound versions.** Valid Lodash ES input becomes invalid JavaScript in Webpack's Harmony imported-identifier transformation. The exact UglifyJS error, independent runtime/parser failures, paired syntax control, full-entry normalization control, and original recurrence establish the cause.

The reporter's exact resolved versions and loader configuration remain unknown. Webpack beta.6 was also available before the report and within the stated range; it was not tested, and no conclusion is asserted for every version allowed by the ranges. Exact reporter-environment equivalence would require the original lockfile/configuration. That limitation does not prevent the narrowed finding above. No further experiment is needed for this demonstrated case.
