# Bug found: discriminated-union types promise an absent runtime property

The reported failure reproduces in **`zod@3.25.0-beta.20250517T081109`**. TypeScript resolves `MyResult.options` to a concrete two-element tuple, but the runtime object has no `options` property. Consequently, `.def.options.length` succeeds and `.options.length` throws.

The cause is a mismatch between interface inheritance and runtime initialization: `ZodDiscriminatedUnion` extends the `ZodUnion` **interface**, but its constructor never executes the classic union initializer that assigns `inst.options = def.options`.

**Qualification:** strict TypeScript 5.8.3 checking also finds four unrelated variance errors in the published library declarations. The report code itself has no diagnostics. These errors were retained, not suppressed; normal emission-on-error enabled execution. This investigation does **not** claim a clean full-library compilation.

## Controls and experiment history

### E1: published package, original snippet

**Hypothesis:** interface inheritance exposes `.options` while runtime initialization omits it. The possible alternative that a discriminator argument is required is contradicted by this beta's explicit array-only overload.

Setup-error logs record an ESM `node -p` failure and relative package-subpath resolution failure (`evidence/initial-harness-error.log`, `evidence/initial-resolution-error.log`). These are harness errors, not reproductions. `evidence/full-typecheck.log` ends at the four library diagnostics; its compiler flags are not recorded there.

**Prediction tested by the retained runner:** with normal emission and every diagnostic retained, expect no original-user-code diagnostics, an additional TS2339 for a bogus property, and the emitted original to fail only at `.options.length`.

**Result:** all predictions held. Both `.def.options` and parsing work. CommonJS also reports `{ defLength: 2, options: undefined }`.

Runtime assertions in `experiments/controls.mjs` hold the option objects and inputs fixed:

| Factory | Internal length | Public alias equals original array | Valid parse | Wrong data / unknown status |
|---|---:|---|---|---|
| `z.union(options)` | 2 | true | accepted | rejected |
| `z.discriminatedUnion(options)` | 2 | false; undefined | accepted | rejected |
| `z.discriminatedUnion('status', options)` | 2 | false; undefined | accepted | rejected |

Thus this is not a failed schema construction, inference degraded to `any`, an overload mistake, or a generally broken options array.

Historical test context, not executed here: `env/npm/package/src/v4/classic/tests/index.test.ts:231–257`, test `"z.discriminatedUnion"`, also uses the array-only call, checks internal options length, and parses both alternatives. It does not assert the public alias in that test.

### E2: isolated causal intervention and recurrence

**Hypothesis/prediction tested:** adding only `inst.options = def.options` in a separate copy of the ESM discriminated-union initializer would expose the promised array without changing validation outcomes; untouched original would continue failing the alias check.

**Result:** `experiments/diagnostic.py` generated exactly that one-line difference. `evidence/diagnostic.log` records the diff and original → variant → original runs. Both variant overloads expose the exact input array, length 2; all parsing controls remain unchanged. Both original runs still lack the alias. The generator writes only the separate copy; verified hashes show that the retained official ESM files and cited source files match the recorded baseline. This isolates the missing public-state initialization; it is not a production repair recommendation.

## Decision and boundaries

**Bug found:** the exact published beta's public type contract and runtime disagree. The inherited `options: T` declaration is non-optional and has no deprecation marker at that declaration; treating it as “legacy” does not make its advertised tuple exist at runtime. Ordinary-union behavior and the one-assignment intervention support the missing-initialization explanation, independently of any documentation policy.

The full repository suite was not run, and no matching Git SHA or reporter-specific toolchain was recovered. The separate declaration variance errors prevent claiming a clean strict build with this reconstructed toolchain, but do not obscure the demonstrated type resolution or runtime failure. No remaining blocker affects this narrowly established defect; no further action is required for this investigation.
