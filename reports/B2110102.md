# B2110102 — Unresolved

**The reported “Invalid range in character set” error was not reproduced.** Moment 2.24.0's Bengali locale has no regex range in its digit character class, and even loading its UTF-8 bytes as Japanese Shift_JIS did not produce that error. The screenshot points to an unavailable generated application bundle, not directly to the published locale file. An encoding mismatch remains a possibility, but the experiments do not establish the report's cause or defect status.

The failing bundle bytes, complete URL, source map, HTML, response encodings, SDK/build configuration, and precise Windows/IE builds are not supplied. A source-map view is not proof of the characters that the browser parsed from the generated response.

### Experiment 1: test the encoding hypothesis at module level

**Hypothesis described in the existing report:** legacy Japanese decoding might turn Bengali regex input into an invalid range; UTF-8 should parse normally. Saved logs do not independently establish that this hypothesis was written before execution.

**Observed:** Node's actual `vm` compiler and Moment modules parsed and registered `bn.js` under UTF-8, Shift_JIS, and Windows-1252 decoding. Wrong decoding corrupted Bengali formatting and prevented strict Bengali date parsing, but raised **no range error**. The script records the digit class's exact code points and confirms it has no hyphen. A scan of individual locales under Shift_JIS found only `be.js`, `el.js`, `ru.js`, and `uk.js` parse failures, all with a different error: `Invalid regular expression: missing /`.

This falsifies the simple claim that the released Bengali digit class necessarily becomes an invalid range under Shift_JIS in this engine. It does not exclude a Chakra-specific issue or a transformed reporter bundle.

**Hypothesis described in the existing report (pre-run timing unverified):** UTF-8 delivery succeeds; inherited Japanese encoding corrupts Bengali but does not reproduce the range error; an explicit UTF-8 script response restores behavior.
