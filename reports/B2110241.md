# Investigation B2110241

## Conclusion: Expected behavior
The reported output is reproduced. `DDDo` is ordinal **day of year**, not day of month. February 9, 2020 is the 40th day of the year. The intended day-of-month output uses `moment().format('MMM Do YYYY')`. Historical tests explicitly support this distinction; no defect demonstrated.

## Observation / expectation
Original report: Moment 2.24.0 on Feb 9, 2020, EST formats `MMM DDDo YYYY` as `Feb 40th 2020`; reporter expects `Feb 9th 2020`.

Acquired official tag `2.24.0`, commit `96d0d6791ab495859d09a868803d31a55c917de1` (tag object `8a6b2e11207a3856bd858d4d65d4b0822571e6c3`). No later source/history or issue discussion consulted. Runtime available: Node v26.12.0, npm 11.20.0, Linux. Repository includes distributable `moment.js`; no dependency installation needed.

Hypothesis before execution: `DDDo` deliberately denotes ordinal day of year (Feb 9 = day 40), while `Do` denotes ordinal day of month. Source registration in `repo/src/lib/units/day-of-year.js:12` and historical English tests (`repo/src/test/locale/en.js:27-59`) support this. Predict the report reproduces with a frozen clock in EST; changing only token to `Do` yields the reporter's desired output. January 9 should make both tokens coincide, February 9 distinguish them. Planned tracing executed ordinal arguments to connect dispatch to output and replaying the historical English format test through the distributed module.

- January 9 control: `DDDo / Do` = `9th / 9th`. February 9 = `40th / 9th`. Leap-year March 1 = `61st / 1st`. Thus the difference is day-of-year semantics, not a special failure of today's date.

This is affirmative historical expectation evidence, not merely absence of a failure.

## Causal path
1. `formattingTokens` in `repo/src/lib/format/format.js:4` recognizes `DDDo` as one token. `makeFormatFunction` (`repo/src/lib/format/format.js:45-63`) compiles its registered function; `formatMoment` (`repo/src/lib/format/format.js:66-75`) invokes the compiled formatter. Executed bundle equivalents: `repo/moment.js:546`, `repo/moment.js:587-605`, and `repo/moment.js:608-617`.
2. The top-level registration in `repo/src/lib/units/day-of-year.js:12` registers `DDDo` as ordinal of `dayOfYear` (base token `DDD`). `getSetDayOfYear` (`repo/src/lib/units/day-of-year.js:33-36`) calculates rounded elapsed local days from year start plus one: 39 + 1 = 40. Executed bundle equivalents: `repo/moment.js:3777` and `repo/moment.js:3798-3801`.
3. `addFormatToken` (`repo/src/lib/format/format.js:16-36`; bundle `repo/moment.js:558-578`) resolves a named getter and calls locale ordinal with the getter result and base token. The experiment's boundary wrapper (`experiments/reproduce.cjs:19-31`) confirms `(40, 'DDD')` rather than `(9, 'D')` in `evidence/reproduce.log:6`.
4. The anonymous English `ordinal` configuration callback (`repo/src/lib/locale/en.js:7-14`; bundle `repo/moment.js:4138-4145`) selects `th` for 40, producing `40th`; month/year token output surrounds it normally. `getSetDayOfYear` calculates using clones and takes its getter branch, so this path does not change the input date.
5. By contrast the top-level registration in `repo/src/lib/units/day-of-month.js:12` (bundle `repo/moment.js:3746`) registers `Do` with getter `date`. The `Moment.prototype` assignments (`repo/src/lib/moment/prototype.js:90-94`; bundle `repo/moment.js:3974-3978`) connect `date` to `getSetDayOfMonth` and `dayOfYear` to `getSetDayOfYear`, hence 9 → `9th` for `Do`.
