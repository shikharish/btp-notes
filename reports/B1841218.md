# Verdict: exact report reproduced

Lodash 4.0.0 `_.merge({}, a, b)` mutates the first source's array element while returning the expected merged destination. Both the published npm package and historical tag reproduce the exact reported values; the command exits 0. Node v26.12.0 on Linux x64 was used, not the reporter's unspecified Node version. The 4.0.0 tag resolves to commit `bf06df447584a0dd4bd55a2a0cf05f88e6e7ed8c`; its `lodash.js` is byte-identical to the npm tarball's (`evidence/provenance.txt`). Reporter lockfile and runtime are unknown.

## Source audit

The causal explanation is supported by the pinned source; no substantive finding is contradicted. References below are workspace-relative. `repo/lodash.js` is the original historical-tag monolithic implementation. The npm baseline actually loads `env/package` from `experiments/baseline.js:2`, through `env/package/package.json:8` (`main`) and `env/package/index.js:1`, into `env/package/lodash.js`. A local hash comparison confirms that this executed package file and `repo/lodash.js` are byte-identical, so their line numbers coincide. Neither `repo/dist/` nor a minified bundle is implicated.

Tracing instead executes generated copies under `experiments/`: `experiments/make-variants.js:9-16` adds three logging statements and creates diagnostic variants. `experiments/trace.js:2-3` supplies the trace identity labels; these are not Lodash behavior. Static comparison confirms the trace copy differs only by those logs, and each intervention adds only the deep-clone argument. This audit checked local files, hashes and the pinned Git commit; it did not rerun experiments or fetch artifacts.

Citation corrections: the array shallow-clone path is `repo/lodash.js:2198-2202`, not the object branch at `repo/lodash.js:2204-2208`; existing plain-object reuse is `repo/lodash.js:3011`, not the `toPlainObject` branch at `repo/lodash.js:3010`; existing-array reuse is `repo/lodash.js:3004-3005`, not the closing brace at `repo/lodash.js:3007`; recursion executes at `repo/lodash.js:3021`, not the comment at `repo/lodash.js:3020`. The primitive write is at `repo/lodash.js:2971` and `repo/lodash.js:2097`, rather than only the branch/function openings at `repo/lodash.js:2966` and `repo/lodash.js:2094`. These were reference errors, not causal errors.

## Causal sequence

1. **OBSERVED/STATIC:** `merge` delegates to `baseMerge` through `createAssigner`, which applies sources left to right (`repo/lodash.js:11143-11145`, `repo/lodash.js:3870-3873`). With a fresh destination, `baseMergeDeep` selects `baseClone(srcValue)` for the first array property (`repo/lodash.js:3003-3006`); `baseClone`'s default shallow array path calls `copyArray`, copying element references (`repo/lodash.js:2198-2202`, `repo/lodash.js:3762-3764`). Trace: new destination array id8, source array id3, but their index 0 is the same object id4 (`evidence/trace-intervention.txt`). This is the earliest observed divergence from source isolation.
2. **OBSERVED/STATIC:** Recursive processing of index 0 in `baseMergeDeep` selects the existing destination value, id4 (`repo/lodash.js:3011`), and calls `baseMerge(id4, id4)` through `mergeFunc` (`repo/lodash.js:3021`); its identity guard returns (`repo/lodash.js:2952-2955`). The reference remains shared.
3. **OBSERVED/STATIC:** The second source reuses destination array id8 and its element id4 in `baseMergeDeep` (`repo/lodash.js:3004-3005`, `repo/lodash.js:3011`). `baseMerge` passes primitive `b: 2` to `assignMergeValue`, which writes it to id4 (`repo/lodash.js:2967-2971`, `repo/lodash.js:2094-2097`), which is also `a.predicates[0]`. Trace shows `PRIMITIVE id4 b 2`; final a and c contain both fields, b is unchanged.

## Controls and intervention

Single-source identity control shows arrays distinct, first elements shared; a one-level plain-object merge and second-only source do not mutate the source (`evidence/baseline.txt`). This contradicts indiscriminate source mutation. Instrumented and uninstrumented outputs agree; tracing uses disposable copies only.

A diagnostic-only change to the missing-array clone call supplies `true` as the deep-clone argument (`experiments/lodash-intervention.js:3006`; traced variant: `experiments/lodash-intervention-trace.js:3008`, both in `baseMergeDeep`). The traced element becomes id9 instead of id4, and `b` is written to id9. The uninstrumented variant preserves a and b while c still contains both fields; the same controls remain correct. Rerunning untouched tag restores the original failure (`evidence/trace-intervention.txt`). This supports causality, not a general repair: a nested plain-object case still mutates its first source with this intervention (`evidence/scope.txt`), and cycles, special values, and broader compatibility were not tested. No source repository files were modified.
