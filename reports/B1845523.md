## Causal sequence

1. **OBSERVED** The exact call returns true/boolean; strict comparisons yield `true` for `=== true` and `false` for `=== 1` (`evidence/baseline.txt`). Both copies gave the same results.
2. **STATIC**, corroborated by the first trace value: non-empty arrays enter `baseSum` through `sumBy` (`repo/lodash.js:16613-16616`). The default `getIteratee` resolves `'bool'` through `baseIteratee`, `property` and `baseProperty` (`repo/lodash.js:5987-5990`, `repo/lodash.js:3500-3514`, `repo/lodash.js:15982-15983`, `repo/lodash.js:892-895`), retrieving the raw property without numeric coercion.
3. **OBSERVED with diagnostic instrumentation; STATIC in original:** in `repo/lodash.js:962-973`, the uninitialized accumulator is undefined, the sole projection is boolean true, and the first-defined-value branch assigns `current` directly instead of applying `+`. The loop ends and returns that boolean to `sumBy` and its caller. `evidence/trace-baseline.txt` records raw/current/prior/branch/result. The earliest relevant divergence from the reporter's desired numeric invariant is this first-value assignment, not the property shorthand.
4. **OBSERVED** A second true reaches the addition branch, producing number 2; a singleton numeric 1 yields number 1 and an empty input yields number 0. An equivalent function iteratee still returns true. Undefined projections are skipped, so a longer array with only one defined boolean also returns a boolean; all undefined returns undefined. Strings demonstrate that native `+` is not universally numeric. See `evidence/baseline.txt` and `evidence/trace-baseline.txt`.

## Intervention, controls and limits

The generated intervention in `experiments/trace-patched.js:970` (`baseSum`), produced by `experiments/make-diagnostic.js:9-19` (`replacement` and top-level writes), converts each boolean projection with `Number(current)` immediately before the existing accumulator branch. This predicts and produces a numeric intermediate and final result: singleton true → 1, false → 0; two trues → 2. Numeric, empty, string-only and undefined controls remain as before, and a three-item callback still executes three times (`evidence/trace-patched.txt`). Rerunning the untouched original reproduces true/boolean and its SHA remains identical to the npm entrypoint (`evidence/restoration.txt`); the repo is clean. Logging was inserted only into generated copies, not the original. `experiments/trace-baseline.js:962-977` retains `baseSum` semantics with logging; `experiments/trace-patched.js:962-978` additionally changes boolean handling. Both retain the public API wiring, but neither is the untouched published entrypoint.

This intervention is **not proof of an API bug or a complete tested repair**: `baseSum` is shared, and compatibility was not exhaustively assessed. In particular, mixed boolean/string values change from `truex` to `1x`, while numeric 1+2 remains 3 (`evidence/compatibility.txt`). Whether such a behavior change is acceptable is a product/API decision. No reporter-side dependency state or actual browser execution was verified; the unmodified published entrypoint was executed directly in Node. No forbidden material or other cases were accessed.
